一、RAG 基础

RAG 是什么？完整链路？为什么需要？
  • 生成前先检索外部知识，拼进 prompt 再生成，获得准确、可溯源、跟得上新知识的回答。
  • 链路：文档入库（切块→嵌入）→ 查询理解 → 多路召回 → 融合/重排 → 拼上下文 → 生成 → 溯源。
  • 需要原因：LLM 知识有截止、会幻觉、无法访问私有数据。对比微调：RAG 灵活可更新可溯源，微调把知识写进参数。
为什么要多路召回？
  • 向量：懂语义，但对精确关键词/缩写/数字不敏感；关键词（BM25）：精确匹配强但不懂语义；图谱：多跳关系推理；联网：时效。
  • 各通道互补，多路并行 + 融合显著提升召回（实测三路较单路 Recall@10 +12.3%）。

二、检索技术

向量检索原理？Embedding？Milvus 索引？
  • Embedding 把文本映射为高维稠密向量，语义相近距离近。
  • 用 ANN 近似最近邻搜索（高维精确太慢）。
  • 索引：HNSW（查询快召回高但占内存）、IVF（聚类倒排省内存）、PQ（量化压缩有损省内存）。
BM25 原理？为什么仍必要？
  • TF-IDF 改进：词频（饱和）、逆文档频率（惩罚常见词）、文档长度归一化。
  • 对专有名词/编号/缩写/精确术语可靠，是语义检索重要补充。
知识图谱 RAG（GraphRAG/LightRAG）vs 普通 RAG？
  • 普通 RAG 切块按相似度检索，割裂文档关系，无法多跳推理。
  • 图谱 RAG 先抽实体关系成图，检索时走图做多跳遍历，回答跨文档关系问题。
  • 代价：图谱构建成本高。LightRAG 五种模式（naive/local/global/hybrid/mix）。

三、融合与排序

RRF 融合？公式？为什么用？
  • score(d) = Σ 1/(k + rank_i(d))，k 通常 60。
  • 优点：用排名而非分数，避免不同通道量纲不可比，无需调权重、鲁棒。
  • 缺点：丢原始分数信息。融合后接 Rerank 精排。
bi-encoder vs cross-encoder？
  • bi-encoder：query/doc 独立编码算相似度，快、可预存，精度略低，用于召回。
  • cross-encoder：query/doc 拼接交互打分，精度高、慢、无法预存，用于精排。
  • 经典：先 bi 召回海量，再 cross 精排少量。
语义分块策略？指标 Recall@K / MRR / NDCG？
  • 分块：固定长度、按标题/段落、语义分块、父子块。太大信息稀释、太小割裂。
  • Recall@K：前 K 命中相关比例（找回来了吗）。
  • MRR：相关文档位置倒数平均（第一个对的排多靠前）。
  • NDCG：含位置权重 + 相关度分级的排序质量。
