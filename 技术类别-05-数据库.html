一、MySQL 索引

为什么用 B+ 树？最左前缀？覆盖索引？
  • B+ 树矮胖、层数少、减少磁盘 IO；叶子成有序链表，范围查询快；非叶子不存数据，查询稳定。
  • 最左前缀：联合索引 (a,b,c) 必须从 a 开始才命中。
  • 覆盖索引：查询列全在索引，不回表。
索引失效场景？
  • 索引列做函数/运算、隐式类型转换、like '%xx' 前导模糊、or 连接非索引列、不满足最左前缀、优化器认为全表扫描更快。

二、事务与锁

ACID？四种隔离级别？
  • ACID：原子性、一致性、隔离性、持久性。
  • 隔离级别：读未提交（脏读）→ 读已提交（不可重复读）→ 可重复读（幻读，InnoDB 基本解决）→ 串行化。默认可重复读。
MVCC 原理？
  • undo log 版本链 + Read View。每行有隐藏事务 ID 和回滚指针，读自己可见的版本，读写不阻塞，实现快照读。
  • 配合当前读（for update）和 Next-Key Lock 解决幻读。
行锁/表锁/间隙锁/Next-Key Lock？乐观锁悲观锁？
  • 行锁锁单行；表锁锁整表；间隙锁锁记录间空隙（防幻读）；Next-Key = 行锁 + 间隙锁。
  • 乐观锁：版本号/CAS 不加锁冲突重试；悲观锁：直接加锁适合高冲突。

三、日志

redo / binlog / undo 区别？两阶段提交？
  • redo：引擎层物理日志，崩溃恢复（持久性），WAL 先写日志。
  • binlog：Server 层逻辑日志，主从复制、恢复。
  • undo：记录旧值，回滚 + MVCC。
  • 两阶段提交：先 redo prepare → 写 binlog → redo commit，保证两者一致。

四、Redis

五种数据类型底层？
  • String(SDS)、List(quicklist)、Hash(ziplist/hashtable)、Set(intset/hashtable)、ZSet(ziplist/skiplist+dict)。
缓存穿透 / 击穿 / 雪崩？
  • 穿透（查不存在数据）：缓存空值、布隆过滤器、参数校验。
  • 击穿（单个热点 key 过期）：互斥锁回源、热点永不过期/逻辑过期。
  • 雪崩（大量 key 同时过期/宕机）：过期加随机值、多级缓存、限流降级、高可用。
持久化 RDB/AOF？过期删除与淘汰？分布式锁？
  • RDB 快照：文件小恢复快，可能丢数据；AOF 命令日志：更安全，文件大。
  • 过期：惰性删除 + 定期删除；淘汰：LRU/LFU 等策略。
  • 分布式锁：SET NX PX 原子加锁 + 唯一 value + Lua 释放，注意续期与误删。
