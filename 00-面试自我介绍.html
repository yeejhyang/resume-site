3-5 分钟完整版（约 1000 字）

面试官您好，我叫杨佳豪，是深圳大学计算机技术专业的硕士应届生。我的定位是「懂训练、懂 Agent、也能写工程」的 AI 应用工程师——从大模型后训练，到 Agent 编排，再到完整的后端落地，我都能独立走通。下面我从教育背景、实习经历、个人项目三个方面介绍自己。

首先是教育背景。我本科在南昌航空大学读数据科学与大数据技术，硕士在深圳大学读计算机技术。本科拿了 4 次学业奖学金、2 次国家励志奖学金，还有计算机设计大赛国赛三等奖、优秀毕业生；硕士拿了 2 次二等奖学金。数据科学 + 计算机技术这条路径，让我既有算法基础，也有扎实的工程功底。

研究生期间，我还参与了中国南山集团的合作项目，做货运车辆的物流数据分析，对车辆运行数据做处理和建模分析，输出物流运营的分析结论，支撑业务决策，锻炼了我的数据分析能力。

然后是实习经历。我在腾讯 CSIG 优图实验室实习了半年，做了两个课题，都是对着真实业务场景去解决的。

第一个是代码生成 Agent 引擎，简单说就是让 AI 听懂一句自然语言的描述，自动把一个应用从写代码一路做到上线。我负责它的架构升级，主要解决「生成太慢」和「一次做出来质量不好」两个问题。效率上，我发现原来的方案里 AI 分了几个角色来回传递信息，容易丢上下文、还重复干活，就把它改成一个人从头做到尾，再配合分级的上下文压缩来控制成本，把整个生成时间从 8 分钟压到 5 分钟；质量上，针对「代码能编译、但一打开就白屏、按钮点了没反应」这种最容易被忽略的问题，我加了一套「编译检查 → 页面渲染检查 → 交互检查 → 修复复查」的流程，用真实浏览器去验证效果，把缺陷率从 29.5% 降到 17.1%。我还和业务一起设计了 20 个真实场景的测试集，让每次改进都有数据可依。

第二个是多模态大模型理解人类意图，用在智能客服、质检这类「视频 + 音频」场景。难点在于：人的真实想法，往往不在他说的话里，而在表情、语气这些细节里——比如「嘴上答应、表情却犹豫」，光看文字判断不出来。而现有模型有两个毛病：一是训练它需要大量人工标注，成本很高；二是它容易偷懒，只抓最明显的那一个信号，忽略其他线索。我设计了一个叫 EVIDE 的训练方案，核心思路是让模型先分头把「看到什么、听到什么」说清楚，再综合起来判断，并且用一套强化学习的方法，让模型知道每个线索到底起了多大作用。最终用一个 7B 的小模型，效果追平了 30B 的大模型，准确率提升 11.5%。这个工作我是第一作者，正在投 AAAI，也申请了专利。

最后是个人项目。我独立开发了一个研发知识检索问答平台（RAG），覆盖了 170 多万篇学术论文，用 Java 写了一套完整的后端。它有三大亮点：第一，多路混合检索——同时用语义、关键词、引用图谱、联网搜索四条通道去找资料，再用 RRF 融合、交叉编码器精排，把"找得全"和"排得准"解耦，检索命中率做到 88.6%，比只用单路向量检索提升了 12.3%；第二，两级精读——先只存论文摘要（单篇约 0.2KB）做全局召回、定位是哪几篇，需要时再按需拉全文精读技术细节，既控住了百万级数据的存储成本，又能答出摘要里没有的深层细节；第三，MCP 对接 + 意图路由——通过 MCP 对接 Semantic Scholar 做论文搜索与引用分析，精读全文时通过它映射到 arXiv 拉取全文，再配合意图路由让模型听懂问题是"查论文、查内部资料还是精读某篇"，分流到对应库或工具。工程侧也走得比较完整，多线程并行、Redis 缓存与限流、RocketMQ 异步入库、模型熔断降级这些都用到了。

总结一下。我的核心竞争力是训练、Agent、工程三位一体——能理解模型的原理去优化它，能编排 Agent 去解决实际问题，也能把系统稳稳地落地上线；同时做过物流数据分析这类传统数据项目，数据分析功底也在。我期待在贵司继续深耕大模型和 Agent 方向，也愿意快速上手任何新技术栈。以上是我的自我介绍，谢谢。
