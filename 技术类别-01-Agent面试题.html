1. 什么是 Agent？与大模型有什么本质不同？

来源：小林面试笔记（xiaolinnote.com）· Agent 基础与核心机制

Agent 定义工具调用记忆机制MCP / A2A
说明：本节聚焦 Agent 面试第 1 题，整合小林面试笔记原文为 Q&A 卡片，点击问题可折叠/展开答案。侧边栏展示全部 16 道子题（其余 15 题待补）。

一、对话引入：面试官的追问

面试官原题：说说你理解的 AI Agent 是什么？

🙋‍♂️ 候选人答（踩坑版）：

  • ❌ 第一轮：「Agent 就是给大模型加了插件，比如 ChatGPT 的插件功能，让它能联网搜索、调用 API 啥的。」
  • ❌ 第二轮：「Agent 就是能调用工具的大模型，给它配几个工具函数，它就能做更多事了。」
  • ❌ 第三轮：「自主……就是它自己决定调哪个工具？」

👔 面试官点评：你说的只是工具调用，跟 Agent 差远了。Agent 最核心的是「自主」——自主规划、多步执行、感知结果再调整，这才是 Agent 的闭环。给它一个目标，它自己把任务拆成多步，一步一步做，每步结果反馈回来再指导下一步，这和普通调工具有本质区别。

✅ 答题要点：抓住一个核心词——「自主闭环」。

二、简要回答

Q1：什么是 Agent？一句话概括

Agent 本质上是一个能自主完成目标的 AI 系统，跟传统 AI 最核心的区别在于「自主性」和「能行动」。

  • 传统 AI：你问一个问题它回答一个问题，每次都是独立的、被动响应。
  • Agent：有自己的规划能力，给它一个复杂目标，它会自己把任务拆成多步，通过调工具、访问记忆、感知环境来一步步执行，直到完成。
  • 它不只是输出文字，而是真的能做事。

三、详细解析

Q2：普通大模型（LLM）的三大局限性？

普通大模型本质上是个「问答机器」，三个局限一环扣一环：

  • ① 知识被冻结：训练数据有截止日期，问它今天天气、最新股价完全不知道，没有任何途径获取实时信息。好比一个人毕业之后再也没看过书。
  • ② 不能行动：让它发邮件、查数据库、执行代码，它只能告诉你「你可以这样做」，但自己做不到。它本质是文本生成器，所有输出都是字符。
  • ③ 没有持续状态：每次调用之间完全失忆，除非手动把之前的对话塞进去，不然它根本不记得上一轮说过什么。
  • 总结：知识是死的、手脚是没有的、记忆是断的，加在一起普通 LLM 只能做「一问一答」，稍微复杂的多步任务完全无能为力。
Q3：Agent 的核心运作闭环是什么？

Agent 有一个核心运作闭环：感知 → 规划 → 行动 → 再感知。

给它一个目标（"帮我调研竞品然后整理成报告"），它不是直接输出一段文字了事，而是：

  • 先拆解任务：要搜索哪些关键词、要访问哪些网站、要怎么组织内容；
  • 然后一步一步去执行，每一步的结果又反馈回来，指导下一步的决策。

这种能力背后由三件核心的事在支撑——工具调用、记忆机制、多步推理与自我纠错。

Q4：Agent 核心能力一：工具调用（Tool Use）

工具调用是让 Agent 从「说话」变成「做事」的关键。Agent 能调用外部工具：搜索引擎、代码执行器、数据库、API 等。

关键认知：模型只负责「决策」——输出调用指令（哪个工具、传什么参数），真正的「执行」由代码完成。这是安全边界：模型不能自己跑代码，必须由外部执行环境去做。

为什么重要：一下子突破前面说的三个局限：

  • 知识被冻结 → 接上搜索引擎，模型就能获取实时信息。
  • 不能行动 → 接上邮件 API、代码执行器，模型就能真正做事。
  • 好比一个人原来只能用嘴说话，现在有了手和脚。

代码示例（定义两个工具「查天气」「发邮件」）：

tools = [
  {
    "name": "get_weather",
    "description": "查询某个城市的天气",
    "parameters": {
      "type": "object",
      "properties": {"city": {"type": "string", "description": "城市名"}},
      "required": ["city"]
    }
  },
  {
    "name": "send_email",
    "description": "发送邮件给指定收件人",
    "parameters": {
      "type": "object",
      "properties": {
        "to": {"type": "string"},
        "subject": {"type": "string"},
        "body": {"type": "string"}
      },
      "required": ["to", "subject", "body"]
    }
  }
]
Q5：Agent 核心能力二：记忆机制

传统 LLM 每次对话都是「失忆」的，Agent 系统通常设计两层记忆：

  • 短期记忆：当前任务执行过程中的中间状态、已经调过哪些工具、拿到了什么结果。保证一个长任务里，Agent 不会中途「失忆」忘了之前做过的步骤。
  • 长期记忆：跨任务、跨会话需要持久化的信息，比如用户偏好、历史交互、领域知识。常用向量数据库存储，按相似度检索相关记忆。

只有「能做事」（工具）+「能记事」（记忆）还差最后一块拼图——也是 Agent 最像「人」的地方。

Q6：Agent 核心能力三：多步推理与自我纠错

这一点经常被忽略，但其实是 Agent 区别于简单自动化脚本的关键。

Agent 在执行过程中如果某一步失败，不会直接崩掉，而是能：

  • 感知到失败 → 分析原因 → 换一种方式重试。
  • 用关键词 A 搜索没找到有用信息 → 自己换关键词 B 再搜一次。
  • 调用某个 API 报错 → 检查参数是否正确 → 修正后重试。

这就像一个真正在「思考」的执行者，碰到障碍会绕路走，而不是一条路走到黑。

更进一步，它还能在完成某一步之后回头审视：我做的这步对不对？结果和预期一致吗？要不要调整后续的计划？

这种「边做边反思」的能力，让 Agent 在面对复杂、不确定的任务时，表现远比死板的自动化流程好得多。

Q7：为什么 Agent 现在才爆发？三个条件

Agent 概念其实很早就有了，但到 2024、2025 年才真正火起来。三个条件同时成熟：

  • ① 大模型能力跨过「能用」门槛：从 GPT-4、Claude 3 这一代开始，模型的推理能力、指令遵循能力才达到「能拆解任务、判断下一步该调哪个工具」的水平。
  • ② 工具调用的标准化：OpenAI 2023 年推出 Function Calling，让模型能以结构化 JSON 格式输出工具调用请求，很快被各家厂商跟进。有了统一协议，工具接入的成本大幅下降。
  • ③ 配套生态的完善：LangChain、LlamaIndex 等框架把 Agent 开发门槛大幅降低；向量数据库解决长期记忆存储；各种 API 服务让可调用工具越来越丰富。
Q8：Agent 生态最新趋势：MCP 与 A2A 两个协议

Agent 越来越多，两个核心问题浮现：工具怎么统一管理？Agent 之间怎么协作？催生了两个非常重要的标准协议。

① MCP（Model Context Protocol，模型上下文协议）

  • Anthropic 在 2024 年底提出，类比 Agent 工具世界的「USB-C 接口」。
  • 没有 MCP 之前，M 个 Agent 框架 × N 个工具 = M×N 套适配代码。MCP 定义一套标准协议，把适配变成 M+N。
  • 三层架构：Host（用户直接交互的 AI 应用，如 Claude Desktop、Cursor）→ Client（负责和 Server 建立连接、管理通信）→ Server（提供具体工具 / 资源）。
  • 2025 年 12 月 Anthropic 把 MCP 正式捐给 Linux 基金会旗下新成立的 Agentic AI Foundation（AAIF），由 Anthropic、Block、OpenAI 等共同维护。

② A2A（Agent2Agent，Agent 间通信协议）

  • Google 2025 年 4 月推出。如果说 MCP 解决「Agent 怎么调工具」，A2A 解决「Agent 怎么协作」。
  • 在多 Agent 系统里，不同 Agent 可能来自不同厂商、用不同框架开发，怎么互相发现对方能力、协调任务、传递中间结果？A2A 的核心设计是一个叫 Agent Card 的东西（类似"能力名片"），让 Agent 之间能互相描述自己会什么、怎么调用。
  • 2025 年 6 月被 Google 捐给 Linux 基金会维护，SAP、Salesforce、ServiceNow 等大厂都在接入。

两者的关系是互补：MCP 管 Agent ↔ 工具的连接；A2A 管 Agent ↔ Agent 的通信。MCP 让每个 Agent 方便「伸手拿工具」；A2A 让多个 Agent 能「互相打招呼、分工合作」。

四、面试总结

Q9：面试踩过的三个雷？怎么避？

三个雷区：

  • 雷一：把 Agent 等同于「插件」或「工具调用」——最常见的误区，工具调用只是 Agent 能力的一部分，不是 Agent 本身。
  • 雷二：停在「能调工具」这一层，没有点出自主性——Agent 关键不是「有工具」，而是「自己决定用不用、什么时候用、用哪个」。
  • 雷三：忽略执行闭环——感知→规划→行动→再感知这个循环才是 Agent 区别于普通 LLM 的核心机制。

答好这道题一定要点出三件事：

  • ① Agent 有自主规划能力，给它一个复杂目标能自己拆解成多步；
  • ② 它能行动，通过工具调用跟外部世界真实交互；
  • ③ 它有闭环，每步结果会反馈回来指导下一步，而不是「问一句答一句」就结束。
Q10：易混淆点：模型是大脑，执行靠代码

一个常被忽略的边界：模型只做推理和决策，不直接执行任何动作。

  • 模型输出"调用工具 X、传参数 Y"——这是决策。
  • 真正去执行 X、拿到结果、把结果拼回上下文——这是外部代码做的。
  • 这个边界既是安全边界（模型不能自己跑任意代码），也是工程边界（执行环境和模型是解耦的，可以替换）。
