一、集合

HashMap 底层？扩容？
  • 数组 + 链表 + 红黑树。JDK8 起链表长度 >8 且数组 >64 转红黑树。
  • 默认容量 16、负载因子 0.75，超过阈值扩容为 2 倍，重新 hash。
  • put 流程：hash → 定位桶 → 冲突链表/红黑树插入。
ConcurrentHashMap 如何保证线程安全？
  • JDK7：分段锁（Segment）；JDK8：CAS + synchronized 锁单个桶头节点，细粒度更高、并发更好。
  • 读操作无锁（volatile 保证可见性），扩容支持多线程协作。
ArrayList vs LinkedList？
  • ArrayList：数组，随机访问 O(1)，中间插入删除 O(n)，适合读多写少。
  • LinkedList：双向链表，随机访问 O(n)，头尾插入删除 O(1)，适合频繁增删。

二、并发与 JVM

synchronized vs Lock？volatile？
  • synchronized：隐式锁，自动加解锁，JVM 层面（偏向锁/轻量锁/重量锁升级）。
  • Lock（ReentrantLock）：显式锁，可中断、可超时、可公平、条件变量，需手动 unlock。
  • volatile：保证可见性 + 禁止指令重排，但不保证原子性。
线程池核心参数？拒绝策略？
  • 七参数：corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、handler。
  • 拒绝策略：AbortPolicy（抛异常）、CallerRunsPolicy（调用者执行）、DiscardPolicy（丢弃）、DiscardOldestPolicy（丢最旧）。
  • 执行流程：先核心线程 → 队列满 → 扩到最大 → 仍满 → 拒绝策略。
ThreadLocal 原理？内存泄漏？
  • 每个线程有自己的 ThreadLocalMap，key 是 ThreadLocal 弱引用，value 是值。
  • 内存泄漏：key 被 GC 后 value 无法访问但还在 map 里，需用完 remove()。
JVM 内存区域？GC 算法？类加载？
  • 区域：堆（新生代 Eden+Survivor、老年代）、方法区（元空间）、虚拟机栈、本地方法栈、程序计数器。
  • GC：可达性分析判定垃圾；算法有标记-清除、复制（新生代）、标记-整理（老年代）；收集器 CMS/G1（G1 分 Region，可预测停顿）。
  • 类加载：加载 → 验证 → 准备 → 解析 → 初始化；双亲委派机制。

三、Spring 与消息队列

Spring IoC / AOP？Bean 生命周期？
  • IoC：对象创建依赖交给容器，@Autowired 注入，核心是 Bean 容器。
  • AOP：抽横切逻辑（日志/鉴权/事务）用代理织入；JDK 动态代理（接口）+ CGLIB（子类）。
  • Bean 生命周期：实例化 → 属性注入 → Aware → 初始化 → 使用 → 销毁。
CompletableFuture 编排？
  • 异步任务编排：thenCombine（合并两个）、allOf（全部完成）、anyOf（任一完成）等。
  • 你的多路召回用 CompletableFuture 四通道并行 + 超时降级。
RocketMQ 可靠性？事务消息？幂等？
  • 可靠性：生产端确认重试、Broker 持久化主从同步、消费端 ACK 重试。
  • 事务消息：半消息 → 执行本地事务 → Commit/Rollback，保证本地事务与消息一致。
  • 幂等：至少一次投递会有重复，用唯一键去重、状态机判断。
MyBatis-Plus vs MyBatis？
  • MyBatis 半自动，手写 SQL；MyBatis-Plus 增强版，内置通用 CRUD、条件构造器、分页插件，保留手写能力。
